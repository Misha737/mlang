Повний чат сесії:

Під час роботи з гітом в VM multipass винкає таке попередження:
warning: unable to unlink '/home/ubuntu/lcd/mlang/.git/objects/maintenance.lock': Operation not permitted

Це попередження безпечне. Воно не псує репозиторій і не вказує на втрату даних.

Причина. Після команд на кшталт commit, fetch чи pull git запускає автоматичне обслуговування (git maintenance run --auto або gc --auto). Воно створює .git/objects/maintenance.lock і видаляє його в кінці. Схоже, що /home/ubuntu/lcd/mlang у вас є змонтованою папкою з Windows (multipass mount C:\dev\mlang ...). На такому маунті (SSHFS чи SMB) видалення файлу, який щойно створено, інколи не проходить через мапінг прав і UID між хостом і VM. Тому виходить Operation not permitted.

Що робити (від найпростішого):

Вимкнути авто-обслуговування в цьому репозиторії. Це прибере і попередження, і спробу створити lock:
git config maintenance.auto false
git config gc.auto 0
Видалити залишковий lock-файл. Якщо він лишився, зробіть це з Windows у PowerShell:
Remove-Item C:\dev\mlang\.git\objects\maintenance.lock -Force
Надійніший варіант: не запускати git на маунті. Склонуйте репозиторій у домашню директорію VM (~/mlang), де файлова система нативна, і синхронізуйтеся з Windows через git push та git pull. Заодно git працюватиме значно швидше, бо на маунтах він повільний.

Якщо ви працюєте з гітом і на Windows, і у VM в одній папці, краще лишити git лише на одній стороні. Інакше можливі проблеми з правами, символами кінця рядка та індексом.

а якщо я хочу працювати в vs code

Так можна, і це кращий варіант за маунт. Є два способи.

1. VS Code Remote-SSH до VM (рекомендую). Код лежить у VM на нативній файловій системі, а VS Code на Windows підключається до неї.

Встановіть розширення Remote - SSH (ms-vscode-remote.remote-ssh).
Додайте свій публічний ключ у VM. Multipass не дає пароля за замовчуванням:
multipass exec <ім'я-vm> -- bash -c "echo '<вміст вашого id_ed25519.pub>' >> ~/.ssh/authorized_keys"
Дізнайтеся IP:
multipass list
У C:\Users\Misha\.ssh\config додайте:
Host mlang-vm
    HostName <IP-з-multipass-list>
    User ubuntu
    IdentityFile ~/.ssh/id_ed25519
У VS Code натисніть F1, виберіть Remote-SSH: Connect to Host… і mlang-vm, потім відкрийте ~/mlang.

Склонуйте репозиторій усередині VM (git clone ... ~/mlang), а не використовуйте маунт. Тоді і термінал, і git, і збірка працюють у VM, а попередження про maintenance.lock зникне.

IP VM може змінитися після перезапуску. Тоді оновіть HostName у конфігу.

2. Лишити маунт і відкривати його з Windows. Відкрийте C:\dev\mlang у VS Code, а збірку й запуск робіть у VM. Це простіше, але git краще запускати лише з одного боку, щоб не було проблем із правами. Для VM-сторони залишіть git config maintenance.auto false. Збірка на маунті теж буде повільнішою.

Якщо вам потрібен просто редактор з підсвіткою, підійде другий спосіб. Якщо ви компілюєте та запускаєте код у VM щодня, краще перший.

як розмонтувати

Розмонтовувати треба з Windows (PowerShell), не з VM.

Спочатку подивіться, що змонтовано:

multipass info <ім'я-vm>

У розділі Mounts буде щось на кшталт C:\dev\mlang => /home/ubuntu/lcd/mlang.

Потім розмонтуйте:

multipass umount <ім'я-vm>:/home/ubuntu/lcd/mlang

Щоб прибрати всі маунти цієї VM одразу:

multipass umount <ім'я-vm>

Файли на Windows у C:\dev\mlang залишаться, зникне лише доступ до них з VM. Порожня папка /home/ubuntu/lcd/mlang у VM лишається, її можна видалити або використати для клону.

Далі склонуйте репозиторій у VM. Спершу видаліть порожню папку, якщо вона заважає:

rmdir ~/lcd/mlang
git clone <url-репозиторію> ~/mlang
